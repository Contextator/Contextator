   The Ingress is enabled but config.trustProxy is not set (or is 0), so TRUST_PROXY stays off:
   the app will not honour X-Forwarded-* headers. Set config.trustProxy (and config.publicBaseUrl)
   to match what actually sits in front of the Pod — see the chart README, "Ingress and reverse
   proxies". If 0 is deliberate, ignore this note.

3) Complete the first-run setup (needsSetup) in the dashboard.

{{- if and (not .Values.secretKey.value) (not .Values.secretKey.existingSecret) }}

NOTE: no SECRET_KEY was provided, so the chart generated one on first install and stored it in
the Secret "{{ include "contextator.secretKeySecretName" . }}". `helm upgrade` keeps that value
(templates/secret.yaml reads it back with `lookup`), but `helm uninstall`, deleting the Secret,
or rendering with `helm template` / a GitOps controller (where `lookup` returns nothing)
replaces it — and stored source tokens (git/Notion) then become undecryptable. Back the Secret
up with your cluster's secret tooling, or pin the key with secretKey.existingSecret; see the
chart README, "SECRET_KEY", for how to do that and how to recover if the key is lost.
{{- end }}

4) Check health (the image ships Node.js only, no wget/curl):
   kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "contextator.fullname" . }} -- node -e "fetch('http://127.0.0.1:{{ .Values.service.targetPort }}/api/health').then(r=>r.text()).then(console.log)"

   or run the chart's own Helm test:
   helm test {{ .Release.Name }}

This chart runs a single replica (see the chart README, "Replicas") and requires an external
PostgreSQL (pgvector) database; there is no embedded PostgreSQL.
